# Секвенсор: функциональная спецификация (черновик)

Документ описывает, **какой функциональностью** должен обладать секвенсор AstraLite.
Это спецификация функций, а не план реализации. Основано на исследовании N.I.N.A.,
SharpCap, KStars/Ekos и CCDciel (см. раздел «Источники»).

## 1. Назначение и принципы

Секвенсор — полностью автоматическая ночная сессия: «настроил, запустил, ушёл».

Принципы (следуют из позиции AstraLite — лёгкая программа для слабых ПК):

- Простая **линейная модель шагов** (список целей + действия), без программируемого
  DSL и плагинов в духе Advanced Sequencer N.I.N.A. Сложность достигается
  небольшим набором встроенных триггеров и политик, а не языком сценариев.
- **Возобновляемость** после сбоя: перезапуск приложения, падение драйвера,
  meridian flip, временная облачность — сессия продолжается, а не начинается заново.
- **Переиспользование** существующих режимов: goto с plate solving, автофокус,
  гидирование и dithering (PHD2 или основная камера), фильтр-колесо, библиотека
  калибровок, фильтр качества кадров. Секвенсор — диспетчер поверх них, не новая
  реализация.
- **Низкая нагрузка на CPU/RAM**: конечный автомат плюс уже существующий пайплайн
  обработки кадров.
- Работа **без монитора** (headless) — целевой сценарий RPi-ригов.

## 2. Основные сущности

| Сущность | Описание |
|---|---|
| **Sequence (последовательность)** | Сохраняемый файл: список целей + глобальные настройки + действия в конце + политики ошибок/безопасности |
| **Target (цель)** | Координаты или имя из каталога, план кадров (по фильтрам: экспозиция, количество, binning/gain/offset/crop), собственные настройки (гидирование, AF, разрешён ли meridian flip (MF), окна старта) |
| **Step (шаг)** | Атомарное действие с условием завершения и политикой ошибок (см. §3) |
| **Template (шаблон)** | Переиспользуемый план кадров / набор шагов (модель CCDciel): например «Narrowband 2h L+R+B+G» |
| **Session (сессия)** | RUNNING-состояние: текущая цель/шаг/кадр, прогресс, журнал событий; persist на диск |

Последовательность и сессия хранятся отдельно: sequence — переиспользуемый файл,
session — состояние для возобновления.

## 3. Шаги, доступные в последовательности

MVP:

- **Slew & Center** — goto с коррекцией по plate solving (существующий `mode_goto` +
  `mode_platesolve`); опционально «centering tolerance» в пикселях и число итераций.
- **Autofocus** — существующий `mode_focusing`; вручную заданные параметры или
  глобальные настройки AF.
- **Change Filter** — переключение фильтр-колеса с ожиданием завершения.
- **Capture N frames** — N экспозиций с указанными параметрами (lights/darks/flats,
  экспозиция, binning, gain, offset, crop); кадры идут через существующий пайплайн
  (калибровка, качество, история) и существующую схему имён файлов.
- **Dither** — dithering существующими средствами (PHD2 или основная камера),
  с ожиданием успокоения (settle).
- **Wait** — N минут / до времени / до конца сумерек / пока высота цели не станет
  ниже заданной; «пока условия не станут безопасными» — фаза 2 (нужен weather
  gate, §4).
- **Device actions** — park/unpark монтировки, прогрев/охлаждение камеры,
  включить/выключить переключатель (dew heater, flat panel). Ограничение: HAL
  сейчас имеет два слота Auxiliary (aux1/aux2) — при нужде расширять.

Meridian flip — не шаг, а автоматический триггер (§4) с разрешением/запретом на
цель (§2): совмещение явного шага и триггера дало бы две конфликтующие точки
управления (модель N.I.N.A./CCDciel — только триггер). Зависимость: самого
meridian flip в приложении ещё нет (README «Future plans»).

Post-MVP:

- **Run Script** — внешний скрипт с контекстом сессии в JSON на stdin (модель Ekos);
  позволяет бэкапы, уведомления, любую интеграцию без раздувания ядра.
- **Sky Flat / Twilight Flat** — автоматические сумеречные флеты (экспозиция
  подстраивается под высоту солнца; модель N.I.N.A./CCDciel).

## 4. Автоматические триггеры и политики (между кадрами)

Настраиваются глобально и с переопределением на цель/план кадров (фазы — см. §15):

- **Dither every N frames** — автоматический dithering по счётчику (MVP).
- **Autofocus триггеры** — после N кадров / через M минут / при росте HFD на X% /
  при изменении температуры (часть уже существует в режиме AF — интегрировать) /
  после meridian flip / после смены фильтра со смещением фокуса на фильтр
  (per-filter focus offset; post-MVP — есть у всех конкурентов, критично для
  рефракторов).
- **Meridian flip триггер** (фаза 2) — по часовому углу/высоте; окно времени;
  пропуск, если переворот невыгоден; разрешение/запрет на цель (§2). Полный цикл
  атомарен: flip → plate solve → recenter → (опц. autofocus) → продолжение той же
  цели. Зависимость: meridian flip ещё не реализован в приложении.
- **Guiding guard** (фаза 2) — RMS гидирования выше лимита → пауза сессии;
  возобновление после восстановления; аборт по таймауту (модель лимитов Ekos).
  Зависимость: текущий `src/guiding` не отдаёт RMS — потребуется доработка.
- **Weather/safety gate** (фаза 2) — INDI SafetyMonitor / датчики (облачность,
  дождь, ветер): «мягкая пауза» или парковка + grace period + автоматическое
  возобновление, когда снова безопасно. Неопределённость сенсора трактовать как
  «небезопасно». Зависимость: HAL пока не поддерживает SafetyMonitor/погодные
  сенсоры — расширение HAL.
- **Cloud detection by camera** (фаза 3) — резкое падение количества звёзд/уровня
  фона между кадрами live view → пауза. Дёшево, реагирует быстрее погодных API.
- **Quality gate** — существующий фильтр качества (FWHM, ovality, температура CCD):
  кадр-браковщик. Помечать брак — MVP; пересъёмка — фаза 2.
- **Disk space guard** — место ниже порога → graceful stop (с действиями конца сессии).

## 5. Предстартовые проверки (preflight)

Перед стартом — чек-лист с явными предупреждениями (модель pre-sequence checks
N.I.N.A.; часть можно запускать при открытии последовательности):

- Все нужные устройства подключены и отвечают.
- Температура камеры ещё не на уставке — предупреждение, не блокировка (ночные
  сессии часто стартуют во время охлаждения).
- Монтировка припаркована/разпаркована согласованно с первым шагом.
- Время: не начинать среди сумерек (или предупреждение); цель выше минимальной высоты.
- Достаточно места на диске; выходной каталог доступен для записи.
- Библиотека дарков/байасов: master-файлы для заданных параметров найдены,
  иначе предупреждение (не блокировка).

## 6. Отказоустойчивость и возобновление

- Состояние сессии пишется на диск атомарно при каждом переходе. Оно является
  первоисточником прогресса; файлы на диске служат сверке и восстановлению при
  повреждении/отсутствии состояния (модель «remember job progress» Ekos /
  checkpoint restart CCDciel). Ключ соответствия файла пункту плана кадров:
  цель + фильтр + экспозиция + binning; файлы, не соответствующие плану, в прогресс
  не входят; забракованные quality gate'ом кадры переснимаются сверх плана.
- После рестарта приложения — предложение продолжить. В headless-режиме
  (`--run-sequence`) диалог невозможен: поведение задаётся опцией —
  авто-возобновление (дефолт) / ожидание / аборт.
- **Политика ошибок шага** (на шаг + глобальный дефолт): повторить N раз с
  backoff → затем пропустить шаг / пропустить цель в этом запуске (ротация целей —
  открытый вопрос, §14) / пауза сессии / аборт.
- Переподключение отвалившегося INDI-драйвера (запланированный crash recovery):
  секвенсор ждёт возврата устройства и продолжает.
- Стоп трёх видов: *Stop after current frame*, *Stop after current target*,
  *Abort now* (с парковкой или без — по настройке).

## 7. Конец сессии (штатный и аварийный)

Набор действий при нормальном завершении; при аборте — тот же набор, но парковка
и прогрев выполняются согласно настройке аборта (§6):

- Park монтировки, прогрев камеры, стоп гидирования, выключить переключатели
  (dew heaters и т.п.), закрыть крышку/шторку (через switch).
- Авто-завершение по утренним сумеркам или заданному времени.
- Итоговое уведомление (журнал; позже — email/webhook, веб-страница статуса).

## 8. Имена файлов и метаданные

- Шаблон имени с макросами: `$$TARGETNAME$$`, `$$FILTER$$`, `$$INDEX$$`,
  `$$DATE$$`, `$$TIME$$`, `$$EXPOSURE$$`, `$$GAIN$$`, `$$CCDTEMP$$` — поверх
  существующего `FileNameUtils` (важно: ключ папки dark-библиотеки не должен
  ломаться шаблоном).
- Богатые FITS-ключи: `OBJECT`, `TARGET`, `OBSERVER`, `OBSERVAT`, `MJD` — опционально,
  post-MVP вместе с GNSS/местом наблюдения.

## 9. UI

- **Редактор последовательности**: таблица целей (имя/координаты, план кадров по
  фильтрам, настройки); добавление целей с карты неба, из поиска по каталогу и из
  последнего решённого поля. Шаблоны плана кадров.
- Глобальные настройки: политики (раздел 4), preflight, действия конца сессии.
- Save/load в JSON.
- **Панель Run**: текущая цель/шаг/кадр, прогресс (кадры сделано/план по целям),
  ETA, журнал событий, кнопки Pause / Resume / Stop (три вида стопа).
- **Test run (dry run)** — прогон шагов без экспозиций: валидация последовательности
  днём (модель daytime test-run SharpCap).
- **Взаимоисключение с ручным управлением**: пока сессия RUNNING, ручные команды
  устройств из панелей (goto, смена фильтра, одиночные экспозиции) блокируются —
  через эксклюзивность команд `src/core/commands.rs` (как в Ekos/N.I.N.A.).
- Редактирование запущенной последовательности — post-MVP (CCDciel умеет).

## 10. Headless и внешний контроль

- CLI: `--run-sequence <файл> [--exit-after-sequence]` — работа без UI на RPi без
  монитора (модель headless N.I.N.A.).
- Статус сессии в JSON (файл или HTTP) — основа для будущей веб-страницы статуса
  (модель CCDciel: любима сообществом за headless-риги).
- JSON-RPC API для скриптов — post-MVP.

## 11. Сценарии на несколько ночей и планирование

- **Окно старта цели** (фаза 3): не начинаться раньше высоты X / времени Y / после
  завершения предыдущей цели (учёт восхода/захода).
- Повтор всей последовательности каждую ночь; «Messier marathon» — повтор списка
  (фаза 3).
- Планировщик мозаик **останется отдельной фичей** (§12), но модель данных цели
  должна содержать поле панели (координаты + поворот), чтобы планировщик мозаик
  мог сгенерировать список целей в последовательность.
- Чередование L/R/G/B по кадрам между целями (interleave) — post-MVP.

## 12. Вне объёма v1 (осознанно)

- Программируемый DSL, визуальные «instruction sets», циклы-условия N.I.N.A.
- Плагин-система.
- Вращатель (rotator) и точная установка угла кадра — устройство пока не
  поддерживается HAL; поля «поворот» в модели данных оставить.
- Полноценный планировщик с приоритетами и preemption (Ekos Scheduler) — цели
  выполняются по порядку; окна старта покрывают большинство реальных нужд.
- Планировщик мозаиков — самостоятельная фича; секвенсор принимает от него лишь
  сгенерированный список целей (§11).

## 13. Точки интеграции с существующим кодом

- Конечный автомат секвенсора — поверх механизма команд (`src/core/commands.rs`)
  и режимов (`mode_goto`, `mode_focusing`, `mode_platesolve`, `mode_waiting`);
  захват кадров — `cam_ctrl` + `frame_processing` (quality gate) + `events`.
- Гидирование/dithering — текущая реализация guiding (PHD2 / основная камера).
  Жизненный цикл в сессии: запуск гидирования при старте, возобновление после MF,
  пауз и длинных Wait, останов в конце (§7).
- Имена файлов — `FileNameUtils`; история сессии и статистика кадров — существующие.
- Настройки последовательности сериализуются как остальные `src/options` (JSON).

## 14. Открытые вопросы

- Расположение файлов последовательностей (каталог options vs. отдельный);
  формат — JSON (§9).
- UI: новая вкладка, диалог или режим главного окна.
- Судьба live stacking внутри секвенсора (секвенсор и live stacking — альтернативные
  режимы захвата v1, или стек тоже шаг?).
- Поведение при отказе цели в середине: перескакивать и возвращаться в конце
  (ротация целей) или идти строго по списку.

## 15. Предлагаемые фазы

1. **MVP**: цели + план кадров; шаги Slew&Center / AF / Filter / Capture / Dither /
   Wait; dither/AF по счётчику; preflight; действия конца сессии; панель Run;
   возобновление (состояние + сверка по файлам на диске); stop-политики;
   блокировка ручного управления на время сессии.
2. Meridian flip полный цикл (зависит от ещё не реализованной фичи приложения);
   weather gate и guiding RMS gate (зависят от расширения HAL и отдачи RMS из
   `src/guiding`); quality gate с пересъёмкой; naming templates; headless CLI;
   dry run.
3. Cloud detection by camera; скрипты + JSON-контекст; веб-статус; окна старта и
   повторы на несколько ночей; сумеречные флеты; импорт целей из планировщика
   мозаик; per-filter focus offsets.
